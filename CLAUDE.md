## Project Overview

Research project investigating how in-context examples influence geometric structures in LLM representations. Bridges Park et al. (2024) "In-Context Learning of Representations" with Lee et al. (2025) "Influence Dynamics and Stagewise Data Attribution".

**Core research question**: Does representational collapse from long/repetitive context degrade LLM safety guardrails?

**Core concept**: Context Sensitivity Scores (CSS) approximate Bayesian Influence Functions (BIF) by measuring covariance between per-token losses and structural metrics across different contexts with frozen model weights.

```
CSS(z_i, Φ) = -Cov_contexts(L(z_i), Φ)
```

CSS is a correlational measure, NOT causal influence (true BIF requires SGLD weight-space sampling).

## Current Research Focus: Safety Collapse Sweep v2

**Default pivot point**: Qwen/Qwen3.5-9B, structured_walk_15, raw wrapping, no injection.

### Key Findings So Far

1. **Incoherence dominates at long contexts** (50K+): Models produce garbled output, not coherent harmful content
2. **Genuine compliance peaks at medium contexts** (2K-10K): The dangerous zone where models still generate coherently but bypass safety
3. **Structure doesn't matter**: Structured walks and random tokens with same vocab produce nearly identical safety degradation (Plot 03)
4. **Smaller models are more vulnerable**: Qwen3.5-0.8B peaks at 24% compliance at 5K tokens (Plot 06)
5. **OLMo-3-7B is remarkably robust**: Maintains ~90% refusal across all context lengths (Plot 04)
6. **Thinking mode helps at medium contexts**: Preserves ~80% refusal through 10K vs dropping earlier without thinking (Plot 05)
7. **Qwen3.5 emits thinking preamble as visible text**: Even with `enable_thinking=False`, the model outputs "Thinking Process:" as regular tokens. Must use `max_new_tokens=500` (not 100) to capture the actual response after the preamble.

## Architecture

### Core Modules (`src/`)

**`src/data/hierarchical_graph.py`** - Stochastic Block Model graph generation
- `HierarchicalGraphConfig`: Configuration dataclass (superclusters, nodes_per_cluster, edge probabilities)
- `HierarchicalGraph`: 3-level hierarchy generator with random walk generation
- `DEFAULT_VOCABULARY`: 96-word vocabulary used for graph node labels

**`src/data/dual_interpretation_graph.py`** - Dual hypothesis graph for collapse experiments
- `DualInterpretationGraph`: Same tokens, two valid SBM clusterings
- `create_graph_with_vocab_size(N)`: Create graph with N-word vocabulary
- `generate_extended_vocabulary(N)`: Generate N unique token strings

**`src/models/hooked_model.py`** - Hook infrastructure for activation extraction
- `HookedLLM`: Main wrapper for any HuggingFace causal LM
- `forward_with_cache()`: Captures activations at specified layers
- `compute_per_token_loss()`: Per-token next-token prediction loss
- Supported architectures: llama, mistral, gpt2, qwen2, qwen3, qwen3_5, olmo3, gemma, gemma2, gemma3

**`src/metrics/structural_influence.py`** - CSS computation engine
- Structural metrics: `DirichletEnergy`, `ClusterSeparation`, `RepresentationCoherence`, `LayerWiseProgress`
- `ContextSensitivityScore`: Core CSS computation (single sample and batch modes)

**`src/metrics/collapse_metrics.py`** - Representational collapse measurements
- `compute_collapse_metrics()`: avg_cos_sim, effective_dim, intrinsic_dim, spread

### Safety Collapse Experiment Pipeline

```
run_safety_sweep.py          # Orchestrator: loops over experiments, handles GPU pinning
  └── run_safety_collapse_experiment.py   # Single experiment: baseline + context + eval
        ├── Phase 1: Load model, baseline audit, LLM judge baseline
        ├── Phase 2: For each (context_type × length × trial):
        │     ├── generate_context_tokens()  →  context token IDs
        │     ├── process_context_chunks()   →  KV cache + collapse metrics
        │     └── evaluate_safety_prompt()   →  refusal/compliance per prompt
        └── Phase 3: Aggregate results, save all_results.json
  └── run_llm_judge_safety.py            # Post-hoc LLM judge (Claude Sonnet batch API)
        ├── Submit batch of (prompt, response) pairs
        ├── Classify: full_refusal / partial_refusal / compliance / incoherent
        └── Save judge/all_results_judged.json
```

### Typical Usage Pattern

```python
from src.data import HierarchicalGraph, HierarchicalGraphConfig
from src.models import HookedLLM
from src.metrics import ClusterSeparation, ContextSensitivityScore

# Generate graph structure
config = HierarchicalGraphConfig(num_superclusters=3, nodes_per_cluster=5, walk_length=50)
graph = HierarchicalGraph(config)
prompt, nodes = graph.generate_random_walk(return_nodes=True)

# Load model and extract activations
model = HookedLLM.from_pretrained("meta-llama/Meta-Llama-3-8B")
output, cache = model.forward_with_cache(prompt, layers=[0, 15, 31])
losses = model.compute_per_token_loss(prompt)

# Compute CSS
metric = ClusterSeparation()
css = ContextSensitivityScore(metric)
result = css.compute_batch(representations, losses, cluster_labels, n_contexts=100)
```

**Key Pattern**: Use `forward_with_cache()` to extract all layer activations in a single forward pass. The `cache` object provides `get_residual_stream(layer_idx)` for layer-specific representations.

## Key Concepts

- **Representational Collapse**: Token representations converging to a low-dimensional manifold after long repetitive context. Measured by avg_cos_sim (higher = more collapsed) and effective_dim (lower = more collapsed).
- **Safety Degradation**: Model fails to refuse harmful prompts after context-induced collapse. Measured as compliance rate among baseline-refused prompts.
- **Three-way classification**: LLM judge classifies each response as refusal (safe), compliance (unsafe), or incoherent (degraded but not dangerous).
- **Dirichlet Energy**: Smoothness of representations over graph structure (lower = smoother)
- **Cluster Separation**: Ratio of inter-cluster to intra-cluster distances
- **Bridge Tokens**: Cluster-crossing positions (structurally important, often show sign flips)

## Hardware Notes

Current: 2x NVIDIA H100 80GB HBM3.

**GPU strategy for sweep v2**:
| Model Category | Backend | GPU |
|---|---|---|
| Qwen3.5 (≤9B) | HF only (no vLLM, flashinfer incompatible) | Single GPU, pin with `--gpu 0` or `--gpu 1` |
| Qwen3.5-27B | HF, `device_map="auto"` | Both GPUs |
| Llama-3.3-70B | vLLM TP=2, `--vllm-enforce-eager` | Both GPUs |
| OLMo-3-7B | vLLM TP=1 or HF | Single GPU |

**Parallel execution**: Run two single-GPU experiments simultaneously by pinning each to a different GPU. The sweep orchestrator supports `--gpu 0` / `--gpu 1` flags.

**Memory budget**: Qwen3.5-9B uses ~18GB in bf16. With 80GB per GPU, 262K context KV cache fits on a single card.

**Important**: Always use `--max-new-tokens 500` for Qwen3/3.5 models. They emit a "Thinking Process:" preamble as visible text even with `enable_thinking=False`. 100 tokens truncates this preamble before the actual response, causing false incoherence classifications.
